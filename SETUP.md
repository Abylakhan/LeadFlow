# LeadFlow — запуск для команды (всё бесплатно)

## Как устроен доступ
- **Главный аккаунт** — `abylakhannurbolat06@icloud.com`. Он единственный администратор: подтверждает сотрудников, меняет цены, контакты и настройки ИИ. Задаётся в `data/config.js` и `supabase.sql`.
- **Сотрудники** сами регистрируются по email на странице входа (вкладка «Регистрация»). Войти они смогут только после того, как администратор подтвердит заявку в Админке → «Команда».
- **Не больше 10 активных сотрудников.** Ограничение проверяют и сайт, и база.
- **Пароли не видит никто**, даже администратор: они хранятся в зашифрованном виде. Если сотрудник забыл пароль, администратор задаёт ему новый.
- **Сотрудник** видит общую базу, но меняет только своих и свободных лидов. Удалять лидов, менять цены, контакты и команду может только администратор.

## 1. База Supabase (10 минут)
1. https://supabase.com → зарегистрироваться → **New project** (тариф Free, регион Frankfurt).
2. **SQL Editor → New query** → вставить весь `supabase.sql` → **Run**.
3. **Authentication → Sign In / Providers → Email**: включено «Enable Email provider», **выключено «Confirm email»** → Save.
4. **Project Settings → API**: скопировать *Project URL* и *anon public key* в `data/config.js`.
5. **Сразу зарегистрируйтесь на сайте с главным email**, раньше всех, и только потом отправляйте ссылку сотрудникам.

## 2. ИИ (бесплатно, ключи меняются автоматически)
1. Один раз разверните функцию: Supabase → **Edge Functions → Deploy a new function → Via Editor**, имя `ai`, вставьте `supabase/functions/ai/index.ts` → Deploy.
2. Получите бесплатные ключи. Чем их больше, тем больше сообщений в день:
   - Google Gemini: https://aistudio.google.com/apikey (лучшее качество)
   - Groq: https://console.groq.com/keys (быстрый запасной)
   - Cerebras: https://cloud.cerebras.ai/ и OpenRouter: https://openrouter.ai/keys (ещё запас)
3. Админка → «ИИ» → вставьте ключ → «Добавить ключ». Сервис определится сам, ключ сразу проверится.

Как работает смена ключей: ИИ берёт лучший сервис (Gemini), а между ключами одного сервиса распределяет запросы равномерно. Если ключ упёрся в лимит, он встаёт на паузу (на 1,5 минуты или на 3 часа при дневном лимите), и запрос сразу уходит на следующий ключ. Неверный ключ отключается сам и помечается в админке. Ключи хранятся на сервере в закрытой таблице, сотрудники их не видят.

## 3. Публикация
GitHub Pages: репозиторий → Settings → Pages → Deploy from branch `main` / root.
Адрес: `https://<логин>.github.io/<репозиторий>/`.

## Защита
- Правила доступа (RLS) работают на сервере: даже через API посторонний не прочитает лидов, а сотрудник не изменит чужого лида.
- Кто и когда изменил лида, записывает сервер, а не браузер.
- Content-Security-Policy запрещает чужие скрипты, библиотека облака проверяется по хэшу (SRI), сайт нельзя встроить в чужую страницу.
- Ссылки из данных пропускаются только с http/https, весь текст экранируется. В CSV-экспорте формулы обезврежены.
- Anon key можно хранить в открытом коде: доступ к данным закрыт правилами RLS.
